**Design input:** [21 — Screenshot-inspired compact grid](../Proposed_prototypes/21-course-details-reference-grid.svg)

## Summary

Update the existing **Course details** screen to follow prototype 21: a compact dark-teal course summary, paired vocabulary totals, and a two-column grid of unit cards. The explicit refinement is to make the top **Focus** and **Supplementary** metric tiles smaller than the prototype: reduce both their typography and padding while keeping the values legible and all course information available.

This is a presentation-only change. Keep course data dynamic, preserve numeric unit order and all existing progress/current-state calculations, and do not alter selection, navigation, persistence, or practice behavior. Do not add dependencies.

## Existing Application Mapping

- The screen is generated by `renderCourseDetails(courseId)` in [`index.html`](../index.html#L7706). It loads course assignments, derives each unit’s progress and current state, and renders the course summary and units.
- The summary currently uses `.course-summary-panel`, `.course-metrics`, and `.course-metric`. Shared metric rules also style the metrics inside unit cards; the new summary sizing must therefore be scoped to the summary panel so it does not accidentally change unit counts.
- `.course-unit-list` is currently a single-column grid. `.course-unit-card` already contains the data and actions needed by the selected design.
- Unit progress is rendered by the existing `<progress>` element; the **Mastered** label is conditional on `stats.mastered`. The **Current** badge is conditional on the selected course/unit pair.
- The delegated handlers already distinguish `select-unit` and `unit-details`. Keep their data attributes and handlers unchanged.
- Course pages and settings share styles in the inline stylesheet in `index.html`. Use selectors scoped to `#coursesContent[data-course-screen="details"]` to avoid unintended changes to the course catalog, Unit details, or Practice format screens.

## Design and Implementation Decisions

### Screen hierarchy

1. Keep the existing Course details page header and Back behavior.
2. Render a full-width course summary panel with the target-language/level badge, full course title, and full description.
3. Place two equal-width metric tiles beneath the description:
   - **Focus** — the course focus-vocabulary count, shown with its unit.
   - **Supplementary** — the course supplementary-vocabulary count, shown with its unit.
4. Keep **Course units** and the dynamic unit count with **numeric order** above the unit grid.
5. Render every unit in numeric order in the compact grid. The selected unit can retain the existing Current treatment.

The prototype’s “14 more units below” is an illustration of scrolling, not a fixed message. Do not hardcode it. The unit count and list must come from the selected course’s data.

### Top Focus and Supplementary tiles

The current shared metric styles use 12px padding, a 10px label, a 16px value, and a 6px label-to-value gap. The selected prototype uses larger tiles than desired. Add smaller summary-only overrides with these targets:

| Property | Target |
|---|---:|
| Tile padding | 6–8px |
| Tile minimum height | Approximately 36–40px, content-driven |
| Label size | 8–9px, bold enough to remain legible |
| Value size | 11–12px |
| Label-to-value gap | 2px |
| Pair gap | 8px |
| Summary metrics block margin | Approximately 8px above and below |

- Keep the metric labels and values dynamic and semantically clear; do not truncate the counts or silently replace them with shortened data.
- Scope the typography and padding overrides to `.course-summary-panel .course-metrics` and `.course-summary-panel .course-metric`. Do not reduce the unit-card metric text by inheriting these top-summary rules.
- Use `min-width: 0`, wrapping, and content-driven height so long labels and localized course values fit at 320px.
- Preserve visible contrast between the deep-teal summary, its text, and both metric tiles. Use the existing theme tokens where possible and check the existing dark-theme override so it does not unintentionally remove the selected teal treatment or reduce contrast.

### Unit grid and cards

- At mobile widths, use two equal columns with `minmax(0, 1fr)` and a compact 8–10px gap, matching the reference composition.
- At wider content widths, allow a third column only when cards remain comfortably readable; do not force the grid to stretch cards or create horizontal scrolling.
- Keep each card’s content in this order: order/title and optional Current badge; full unit description; focus and supplementary counts; progress bar and percentage with optional Mastered state; Select and Details actions.
- Reduce card padding and visual chrome enough to create a compact card, but do not use fixed heights. Long titles and descriptions must expand and wrap rather than clip or overlap.
- Keep the unit-level metrics concise and distinct from the top course totals. Do not apply the top-summary font-size reduction globally.
- Keep both actions visible and separately operable. Preserve the existing button labels, action data attributes, progress element, and accessible progress label.

### Styling, themes, and responsiveness

- Use the prototype’s light page surface, dark-teal summary, white/light metric tiles, green unit accent, and blue-violet actions as the visual direction.
- Preserve the application’s existing theme behavior. Summary text and metric tiles must remain readable in both light and dark themes; do not assume white tile backgrounds when the active theme supplies dark surfaces.
- At 320px, retain two unit columns, allow labels and descriptions to wrap, and prevent horizontal overflow. At 390px, match the reference grid proportions. At wider widths, increase the grid column count only when each card has sufficient width.
- Keep the page scrollable so all units remain available; do not hide units behind new tabs or disclosure controls.

## Behavior and Accessibility Constraints

- Opening Course details, Back navigation, clicking a unit card, and the Select and Details buttons must behave exactly as they do now.
- Do not change course parsing, course totals, progress calculations, mastery thresholds, current-unit selection, local storage, or practice sessions.
- Preserve numeric ordering and dynamic unit counts. Do not duplicate the current unit as a second course unit.
- Preserve the `<progress>` element and its accessible label. Keep the conditional Mastered text and Current badge available as text, not color alone.
- Maintain visible keyboard focus on unit cards and actions. Ensure card-level activation does not swallow activation of either nested button.
- Keep action targets usable by touch; compact styling must not reduce them below the existing practical hit area.
- No functional documentation or local-storage documentation changes are expected because this plan changes presentation only.
